About

      
Three years under the mainframe.

      

        

          
My first job put me on Db2 for z/OS: JCL, EBCDIC, packed decimals, system catalogs. It is an unfashionable stack, and it taught me the lesson every data engineer learns eventually. Data rarely fails loudly. It fails in a date format, an encoding or a null indicator that nobody checked.

          
Today I'm on the extraction side of a mainframe-to-AWS migration for a global automotive and fleet client. Alongside it, I build the rest of the journey: pipelines that land raw data safely, validate every record and serve tables people can trust.

          
I started locally with Airflow, Spark and Kafka. Then I rebuilt the work on AWS: deployed on a real account, tested, documented, and torn down when idle so it costs nothing.

          The bug that became the template
          
Loads were failing quietly on dates.

          
Db2 on z/OS wrote dates as MM/DD/YYYY. Db2 LUW on AWS expected ISO. The loads looked fine until they didn't. I traced the problem to the unload stage instead of the load, fixed the extraction format there, and that fix became the standard used in every later wave.

          

            10/14/2026z/OS unload→2026-10-14ISO for Db2 LUW

Incident log

        
What broke, and what I changed.

        

          

            
Lakehouse · data qualityGate blocked

            
The quality gate failed a file that was perfectly valid.

            

              
Saw
The India file failed the 95% gate with zero invalid rows.

              
Cause
4,894 exact duplicates (13.1%) were scored as if they were corrupt.

              
Fix
Changed the metric, not the threshold: validity = (clean + duplicates) / total. Duplicates are still quarantined.

            

          

          

            
Lakehouse · networkingJob timeout

            
Adding Iceberg made a Glue job time out.

            

              
Saw
Connect to glue.<region>.amazonaws.com:443 timed out after three retries.

              
Cause
The job ran inside the VPC for Redshift, and nothing gave it a private path to the Glue Catalog API.

              
Fix
Added a Glue interface endpoint. Still no NAT gateway, and no code change.

            

          

          

            
Telemetry · securityTrust bug

            
An IoT rule trusted the message instead of the device.

            

              
Saw
A bad-data test without vehicle_id broke the DynamoDB rule.

              
Cause
The rule read the ID from the payload, which any sender can fake.

              
Fix
All three rules now take the ID from the certificate-bound topic. The payload ID is only compared and flagged.

            

          

          

            
Lakehouse · orderingConnection timeout

            
dbt couldn't reach a warehouse that looked healthy.

            

              
Saw
dbt timed out after four minutes, while Data API checks had just passed.

              
Cause
The Data API uses the control plane. dbt uses the network, and the workgroup was private because a later step had run first.

              
Fix
A script that opens the workgroup to one IP, runs dbt, and closes it again.

Next build

          In design · building next
          
One spec. Batch, streaming or hybrid.

          
SpecFlow (working title) is the project I'm designing next: an AI-assisted, human-approved pipeline builder. You drop a file or connect a live feed. It profiles every field, proposes cleaning steps and business metrics, and asks you only where a wrong guess would be costly. You approve a plan, and a tested engine runs it into Iceberg tables and a dashboard.

        

        
    
          
  • The AI plans. The engine executes.The model writes a validated JSON spec, never code that runs.
    • 
          
  • Every step shows its why.Approve, edit or reject each one. Nothing is applied silently.
    • 
          
  • One spec, three modes.The same approved plan runs as batch, streaming or a hybrid of both, merging on a business key.
    •
