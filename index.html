About

      
Three years under the mainframe.

      

        

          
My first job put me on Db2 for z/OS: JCL, EBCDIC, packed decimals, system catalogs. It is an unfashionable stack, and it taught me the lesson every data engineer learns eventually. Data rarely fails loudly. It fails in a date format, an encoding or a null indicator that nobody checked.

          
Today I'm on the extraction side of a mainframe-to-AWS migration for a global automotive and fleet client. Alongside it, I build the rest of the journey: pipelines that land raw data safely, validate every record and serve tables people can trust.

          
I started locally with Airflow, Spark and Kafka. Then I rebuilt the work on AWS: deployed on a real account, tested, documented, and torn down when idle so it costs nothing.

          The bug that became the template
          
Loads were failing quietly on dates.

          
Db2 on z/OS wrote dates as MM/DD/YYYY. Db2 LUW on AWS expected ISO. The loads looked fine until they didn't. I traced the problem to the unload stage instead of the load, fixed the extraction format there, and that fix became the standard used in every later wave.

          

            10/14/2026z/OS unload→2026-10-14ISO for Db2 LUW

IoT · streamingKinesisCloudFormationv5.0 · Oct 2026

            
Connected-car telemetry on AWS

            
Tyre pressure, pedal and fuel readings from simulated cars, sent over MQTT. The pipeline validates each reading, stores the history as Parquet for SQL, keeps the newest valid state of every car, e-mails an alert when a tyre drops below 28 psi, notices when a car goes silent and answers questions in plain English. Version 5.0 rebuilt it on a Kinesis stream after I worked out where the first design would stop scaling.

  • One certificate per car. A device can publish only to its own topic, and every rule reads the vehicle ID from the topic. A spoofing test was rejected by AWS IoT.
    • 
          
  • Schema drift without data loss. The validation Lambda types and range-checks fields, keeps unknown fields in extras and flags problems in dq_issues.
    •

    •

    • 
          
  • Failures are visible. Retries, then a dead-letter queue; 12 alarms for throttling, lag, Parquet conversion and Lambda errors; an offline check e-mails when cars go silent.

Incident log

        
What broke, and what I changed.

        

          

            
Lakehouse · data qualityGate blocked

            
The quality gate failed a file that was perfectly valid.

            

              
Saw
The India file failed the 95% gate with zero invalid rows.

              
Cause
4,894 exact duplicates (13.1%) were scored as if they were corrupt.

              
Fix
Changed the metric, not the threshold: validity = (clean + duplicates) / total. Duplicates are still quarantined.

            

          

          

            
Lakehouse · networkingJob timeout

            
Adding Iceberg made a Glue job time out.

            

              
Saw
Connect to glue.<region>.amazonaws.com:443 timed out after three retries.

              
Cause
The job ran inside the VPC for Redshift, and nothing gave it a private path to the Glue Catalog API.

              
Fix
Added a Glue interface endpoint. Still no NAT gateway, and no code change.

            

          

          

            
Telemetry · securityTrust bug

            
An IoT rule trusted the message instead of the device.

            

              
Saw
A bad-data test without vehicle_id broke the DynamoDB rule.

              
Cause
The rule read the ID from the payload, which any sender can fake.

              
Fix
All three rules now take the ID from the certificate-bound topic. The payload ID is only compared and flagged.

            

          

          

            
Telemetry · operationsStuck tear-down

            
The tear-down stopped half-way and left a bill running.

            

              
Saw
Thing CAR-101 is still attached to one or more principals, an empty $BUCKET and a stack stuck in DELETE_FAILED.

              
Cause
A second provisioning run replaced the local certificate record, so the old certificate stayed attached. The commands trusted local files instead of AWS.

              
Fix
One script that asks AWS what exists, deletes in the right order, retries known failures and checks 18 resource types until ALL CLEAN.

            

          

          

            
Telemetry · scaleDesign review

            
The first design would have stopped at about 1,000 cars.

            

              
Saw
On paper, Firehose Direct PUT allows 1,000 requests a second per stream in Mumbai, and each message was one request.

              
Cause
No buffer between IoT Core and its consumers: no replay, no ordering, one alert per reading, and late data could overwrite newer state.

              
Fix
A Kinesis stream in front, Parquet history, a state Lambda where the newest valid reading wins, then a load test and a resilience test on AWS to prove it.

            

          

          

            
Lakehouse · orderingConnection timeout

            
dbt couldn't reach a warehouse that looked healthy.

            

              
Saw
dbt timed out after four minutes, while Data API checks had just passed.

              
Cause
The Data API uses the control plane. dbt uses the network, and the workgroup was private because a later step had run first.

              
Fix
A script that opens the workgroup to one IP, runs dbt, and closes it again.

            

          

          

            
SpecFlow · AI plannerPlan rejected

            
Every AI plan arrived with its parameters missing.

            

              
Saw
Gemini's plans failed validation with name Field required on every step that takes parameters.

              
Cause
The tool schema declared step parameters as an object with no listed fields. Gemini's OpenAI-compatible endpoint returned {} for it.

              
Fix
Parameters now travel as a JSON string for OpenAI-compatible models. The validator caught it every time, so only the rules plan ever ran.

            

          

          

            
SpecFlow · ingestionLoad failed

            
Real Kaggle files broke CSV auto-detection.

            

              
Saw
DuckDB: not possible to automatically detect the CSV parsing dialect on USvideos.csv.

              
Cause
Multi-line quoted descriptions, quotes inside quotes and mixed encodings, which synthetic test data never had.

              
Fix
A fallback ladder: auto-detect, then explicit quote rules, Latin-1, then tolerant parsing, with bad rows counted as malformed. All 78,301 rows loaded.

            

          

          

            
SpecFlow · SparkCI red

            
Spark lost the quotes around a T in a date format.

            

              
Saw
The first Spark run in CI failed on Unknown pattern letter: T. The same spec passed on DuckDB.

              
Cause
SpecFlow escaped quotes the SQL-standard way, ''. Spark reads that as two strings glued together, so 'T' became a bare T.

              
Fix
Backslash escaping for Spark, a parser policy that sends bad dates to quarantine instead of throwing, and tests that fail on the old output.

            

          

          

            
SpecFlow · streamingTest failed

            
The crash test crashed. The pipeline didn't.

            

              
Saw
Replaying batch 1 died with Multiple streaming queries are concurrently using …/commits.

              
Cause
To fake a crash the test deleted Spark's commit file but left Hadoop's hidden .1.crc checksum, which a real crash never leaves.

              
Fix
The test removes both. The replay then merged 206 rows, added none and kept the watermark.

Latest build

          v1.1 · green in CI on Spark + Kafka · AWS run next
          
One spec. Batch, streaming or hybrid.

          
SpecFlow is an AI-assisted, human-approved pipeline builder that I designed and built. You drop a file or connect a live feed. It profiles every field, proposes cleaning steps and business metrics, and asks you only where a wrong guess would be costly. You approve a plan, and a tested engine runs it into Silver, Gold and Quarantine tables and a dashboard: DuckDB on a laptop, Spark Structured Streaming on Kafka, Apache Iceberg on AWS. Every column it writes can be traced back to its source.

          

            
          

        

        
    
          
  • The AI plans. The engine executes.The model writes a validated JSON spec, never code that runs.
    • 
          
  • Every step shows its why.Approve, edit or reject each one. Nothing is applied silently.
    • 
          
  • One spec, every engine.The same approved plan runs as batch, streaming or hybrid, on DuckDB or Spark, merging on a business key.
    •

        • The AI never writes code. Gemini, Bedrock or Claude returns a JSON plan through tool use and sees only a masked profile. The plan is checked for schema, column references and SQL safety, then dry-run. If it fails, the rules plan is used.
          • 
        
        • It asks instead of guessing. Business metrics, dedupe keys and personal data become questions with options. Nothing runs until a person approves the spec.
          • 
        
        • Every row is accounted for. Each run checks that rows in equal clean plus quarantined plus malformed. A failing error-level check blocks publishing, and every rejected row keeps a reason code.
          • 
        
        • One spec, three modes. Batch, micro-batch streaming with a watermark and dead letter, or a backfill followed by a live feed. Replays merge on the business key, so they never duplicate.
          • 
        
        • Streaming at scale on Spark. The same spec runs as Spark Structured Streaming on Kafka, Amazon MSK or Kinesis: an exact layer that merges into Iceberg and survives a crash, plus a live layer with an event-time watermark and RocksDB state.
          • 
        
        • Lineage, catalog and cost. Every column traced to its source in a Lineage tab and in OpenLineage events, notes written into the Glue Data Catalog, personal-data columns tagged for Lake Formation, and the cost of each AWS run measured.
